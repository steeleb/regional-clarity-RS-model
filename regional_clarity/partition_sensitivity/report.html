Regional Clarity RS Model · Partition Sensitivity

Is the HUC4 split unlucky, or is this problem structural?

The outlier-HUC investigation found that partitions 3 and 5 concentrate the region's hardest-to-predict basins - a forested glacial-lake cluster (HUC4 1701) and a large, dynamic reservoir (Lake Powell, HUC4 1407) - almost entirely within one fold each. This follow-up asks whether that's a one-off consequence of a single HUC4-grouped 5-way split, or something that shows up under any similar partitioning choice: rotating which partition is held out, and reassigning partitions at the finer HUC8 level (both deterministically and under 10 random-but-balanced reassignments).

The question

One split told us where the hard basins are. Was it also just unlucky?

The outlier-HUC investigation traced partitions 3 and 5's underperformance to a universal high-clarity compression bias, concentrated by chance into two folds: partition 3 inherited essentially all of HUC4 1701 (a cluster of deep, forested, naturally clear glacial lakes), and partition 5 inherited essentially all of HUC4 1407 (dominated by Lake Powell, a large and hydrologically dynamic reservoir). That report's recommendation was to stop relying on a single fixed split and build a larger ensemble across multiple partition assignments instead. This follow-up tests that recommendation directly: does rotating which partition serves as the test set reproduce the same pattern everywhere it could occur, and does moving to a finer spatial grouping (HUC8 instead of HUC4) - either with the same algorithm or a randomized variant - actually reduce how much a single fold's score depends on which basins happened to land in it?

A third question from the original ask - whether reseeding the HUC4-to-partition assignment process itself changes anything - turned out to be moot: the assignment in 03_split_data.Rmd is a fully deterministic greedy bin-packing (HUC4s sorted by row count, each one dropped into whichever of 5 running partitions is currently smallest), with no random component to reseed. That's why the sensitivity questions here are about partition rotation and spatial resolution instead.

Method

Fixed models, rotated partitions - isolating the split from the modeling choices

Every experiment below reuses the exact final tuned hyperparameters for xgboost and lightgbm from outlier_rework, the same intersection-16 feature set, and the same SDD-weighted training scheme (k=2.0) - nothing is retuned. This is a deliberate choice: it isolates the effect of how rows get assigned to partitions from the effect of model selection, so a change in results can be attributed to the split, not to a different hyperparameter search finding a different optimum. (The NN was excluded from this round to keep iteration fast and avoid its process-isolation overhead; it was not a source of the pattern being tested here.)

For a given partition scheme and a given held-out test partition, the other 4 partitions become leave-one-out CV folds - identical in structure to the production pipeline's spatial CV. One model is trained per fold, the 4 fold models' predictions on the held-out test partition are averaged, and test-set RMSE/MAE are recorded. Every partition takes a turn as the test set, for three kinds of partition scheme:

  • HUC4 baseline - today's actual grouping (5 rotations)
  • HUC8 greedy - the identical greedy bin-packing algorithm, run on HUC8 sub-basins instead of HUC4 basins (5 rotations). HUC8 was already assigned per site upstream in the AquaMatch pipeline (spatially joined against NHD/WBD HUC8 polygons), so no new geospatial work was needed - just confirming coverage and joining it in. 197 HUC8 units subdivide the 33 HUC4 basins in this dataset.
  • HUC8 random-balanced - same bin-packing objective (still greedy-assign to the currently-smallest partition, so sizes stay balanced) but with HUC8 processing order randomly shuffled instead of strictly size-sorted, repeated across 10 seeds (5 rotations each, 50 total)

120 test-partition × model combinations in total (60 rotations × 2 models), each rotation training 4 fold models - 480 model fits, run directly rather than retuned or approximated.

Task 1

Rotating the current HUC4 split: not a fluke of which partition is "test"

Circulating the test-set role across all 5 of today's HUC4-grouped partitions confirms the pattern is structural to this particular split, not an artifact of partition 5 specifically having been chosen as the test set. Partitions 3 and 5 are worse under every rotation that holds them out (RMSE 1.76–1.86 m), while partitions 1, 2, and 4 stay in a tighter, lower band (RMSE 1.17–1.44 m) regardless of which one plays test.

This matters because it rules out an easy alternative explanation - that partition 5 just happened to be an unlucky choice for the test role, and a different choice would have looked fine. It wouldn't have: partition 3 is exactly as bad when it plays test instead of CV-fold, because the basins that make it hard (HUC4 1701) don't move - they're locked into partition 3 by the original assignment regardless of which partition is designated "test" that day. The disparity is a property of the HUC4-to-partition assignment itself, not of which partition a downstream script happens to label as held-out.

Task 3a

Finer spatial units alone don't fix it - they relocate it

HUC4 1701's 1,363 rows are actually spread across 20 separate HUC8 sub-basins, and HUC4 1407's 642 rows across 4. In principle, grouping at the HUC8 level instead of HUC4 gives the size-balancing algorithm 197 units to distribute instead of 33, which should make it much less likely that an entire hard cluster lands in one partition by chance. In practice, running the identical greedy bin-packing algorithm on HUC8 units doesn't reliably deliver that: HUC4 1701 still lands 73% concentrated in a single partition (partition 4), because greedy bin-packing processes units in strict size-descending order, and several of 1701's largest HUC8 sub-basins - including its single biggest, 592 rows - happen to be size-adjacent enough to get assigned to the same "currently smallest" partition back-to-back, before enough other regions' units arrive to break up the run.

The practical result: partition 3, the worst-performing fold under HUC4 grouping, becomes the best-performing fold under HUC8 greedy (RMSE drops to 1.15–1.18 m) - because that's where 1701's hardest rows used to sit, and they've moved elsewhere. But partition 4 becomes the new worst (RMSE 1.89 m for both models), marginally worse than HUC4 grouping's own worst case (1.86 m). Lake Powell's HUC4 1407 fares better under the same scheme - its concentration drops from 100% to 47% - but that 47% isn't really an achievement of the algorithm: with only 4 HUC8 sub-basins and one of them alone accounting for 302 of 642 rows, no assignment of the remaining pieces can bring the largest single partition's share below roughly 47%. That floor is set by the size of Lake Powell's biggest sub-basin, not by how cleverly the units are distributed.

The lesson from this experiment

Switching to a finer spatial unit is not, by itself, a fix - it's the same greedy algorithm with different inputs, and a purely size-based greedy algorithm has no notion of "these units are all part of the same hard regime, spread them out." It can just as easily concentrate them into one bin as the coarser HUC4 version did, particularly when several large, similar-sized units from the same region get processed consecutively.

Task 3b

Randomizing the assignment order helps, on average - unevenly

Breaking the strict size-sorted processing order - shuffling which order HUC8 units get considered, while still greedily assigning each to the currently-smallest partition so sizes stay balanced - removes the correlation that let same-region units land together by sequence alone. Across 10 independent random seeds, HUC4 1701's concentration in its largest partition ranged from 43.9% to 66.0% (mean 54%), compared to a fixed 73.3% under size-sorted greedy and 100% under HUC4 grouping. Lake Powell's concentration stayed pinned near its ~47% floor regardless of seed, exactly as expected given that floor is set by sub-basin size, not assignment order.

That translates into a real, but partial and seed-dependent, reduction in how much test RMSE swings depending on which partition is held out. Averaged across the 10 seeds, the standard deviation of test RMSE across the 5 rotations was 10–18% lower than under today's HUC4 grouping (xgboost: 0.256 vs. 0.285; lightgbm: 0.261 vs. 0.313). But that average hides real spread: the best seed (a lower-concentration draw) cut the rotation-to-rotation spread roughly in half (sd ≈ 0.16–0.19), while the worst seed actually exceeded today's HUC4-grouping spread (sd ≈ 0.32–0.33). There's a real but weak relationship between how concentrated HUC4 1701 ends up in one partition and how much that scheme's rotation results vary (r≈0.35 across the 11 HUC8 schemes tested) - directionally consistent with the mechanism, but far from the only thing driving it, since other basins' arrangement in the same random draw matters too.

No single "better" split, but a real average benefit

There is no one alternative partitioning choice tested here that reliably beats today's HUC4 split for every rotation. What the 10-seed spread shows instead is a distribution: most random reassignments modestly reduce how much a fold's score depends on which basins it happened to inherit, a few reduce it substantially, and at least one did not help at all. That's exactly the argument for ensembling across several split assignments rather than searching for a single "correct" one - any individual split, including a well-intentioned redesign, carries its own luck of the draw.

Before implementing

Do the problem HUCs' assignment change upstream decisions too?

The next step this report points toward is building a production ensemble across multiple partition assignments. Before doing that, it's worth asking a different question: were the decisions that came before the final models - which features backward elimination kept, and what hyperparameters tuning chose - made on a CV pool that itself under-represented Lake Powell and unevenly distributed HUC4 1701, in the same way the final-evaluation numbers were? If so, the feature set and hyperparameters the new ensemble workflow would inherit might themselves be worth revisiting, not just the split design.

This is a spot check, not a re-run of the full pipeline: the correlation-pruned 22-candidate starting pool and each model's fixed "optical+site+weather" hyperparameters (used to hold hyperparameters constant during elimination, exactly as production did) are frozen at their actual production values. The only thing that changes is which rows land in which of the 4 CV folds vs. the held-out test partition - backward elimination and gap-aware hyperparameter tuning are then re-run exactly as production ran them, under two alternate partition schemes: HUC8 greedy (deterministic, from above) and HUC8 random seed 3 (the seed with the lowest HUC4 1701 concentration found in the earlier sweep, as a contrasting draw). xgboost + lightgbm only, matching this project's scope throughout.

Feature selection: the core 16 hold up, but two dropped features look like they shouldn't have been

16 of the 22 correlation-pruned candidates are kept in all six runs tested - today's production xgboost and lightgbm elimination, and both models rerun under both alternate schemes. Those 16 are exactly today's intersection-16 feature set: the core feature set is not in question here. But two candidates - swir1_corr7 and tmax_degC_prev30 - were dropped by production for both models, and kept by every one of the four alternate-scheme reruns. That's a 4-for-4 result, not a coin flip.

Elimination also stopped noticeably earlier under both alternate schemes - production dropped 4-5 of the 22 candidates before hitting its stop condition; the alternate reruns dropped only 1-3. That's consistent with the mechanism this whole report has been describing: once the hard, high-variance basins are spread more evenly across the 4 CV folds instead of concentrated in one, each fold's validation set is a little less uniform, and it takes more real signal to make a feature look clearly redundant with the shadow-permutation noise floor everywhere at once.

What this means

swir1_corr7 (shortwave-infrared reflectance) and tmax_degC_prev30 (antecedent 30-day max temperature) look like consistent casualties of running elimination against a CV pool that walled off nearly all of Lake Powell and never spread HUC4 1701 across more than one fold at a time. Both have a physically plausible story for mattering specifically to these basins - SWIR reflectance tracks turbidity/moisture in ways a large, sediment-influenced reservoir could exercise more than the rest of the region, and antecedent temperature could matter for a reservoir whose optical regime tracks seasonal inflow and lake-level change. Neither is proof they belong in the final feature set - but the current intersection-16 was chosen without ever giving them a fair test against CV folds that actually contained much of the basin they'd plausibly help with.

The higher validation RMSE under both alternate schemes isn't evidence the model got worse - it's the opposite kind of signal. Production's CV pool walled off most of Lake Powell into the untouched test set, so its validation RMSE during tuning never had to face that basin's difficulty. The alternate schemes' CV folds include much more of it, so their validation RMSE reflects a harder, more representative task, not a regression. That framing is reinforced by the gap column: xgboost's train-val gap under HUC8 seed 3 (0.307) is meaningfully smaller than production's (0.375), despite the harder validation task - a hint that more representative exposure to hard basins during tuning can improve generalization rather than hurt it.

Architecture ranking: stable between xgboost and lightgbm, untested for the NN

Reusing the rotation results from earlier in this report: lightgbm's mean test RMSE across rotations is narrowly ahead of xgboost's under HUC4 baseline (1.497 vs. 1.513), HUC8 greedy (1.466 vs. 1.471), and the 10 pooled random seeds (1.478 vs. 1.478, effectively tied) - no scheme flips which of the two looks better. But the NN was excluded from every experiment in this project, both the rotation-sensitivity work and this spot check, to avoid its process-isolation overhead. Whether the NN's place in the production ensemble - or the ensemble weights themselves - would look different under a different split is the one architecture-level question this work leaves entirely open.

Verdict: worth a more formal revisit before implementing

This was a spot check, not a full re-selection - two alternate schemes, starting hyperparameters and the correlation-pruned candidate pool held fixed rather than re-derived, no NN. But the signal is consistent enough to act on rather than wave away: two specific features show a clean, repeated case for reconsideration rather than a coin flip; xgboost's hyperparameters shift by a real amount; and elimination's stopping point in general looks sensitive to how evenly the hard regimes are spread across CV folds. Before building the ensemble-of-splits production workflow on today's fixed intersection-16 feature set and hyperparameters, it's worth re-running backward elimination and gap-aware tuning across the actual ensemble of partition assignments that workflow will use (or a small handful of them, e.g. 3-5 random-HUC8 seeds) and taking a consensus feature set and hyperparameter choice from that - the same cross-fold-consensus logic already used to reconcile the three models' separate elimination paths, extended one level up to reconcile across split assignments too.

Conclusion

The split-concentration problem is real and structural - and no single alternative split removes it

Rotating the test-partition role across today's HUC4 grouping confirms that partitions 3 and 5's underperformance isn't an accident of which partition a script happened to label "test" - it's a direct, deterministic consequence of a single HUC4-to-partition assignment that locks each hard basin (HUC4 1701, HUC4 1407) entirely into one fold. Moving to finer HUC8 units doesn't inherently solve this: with the same size-based greedy algorithm, it just as readily concentrates the same hard cluster into a different fold, occasionally producing a rotation modestly worse than today's worst case. Only when the assignment order is randomized - not just the unit size - does the concentration meaningfully loosen, and even then inconsistently: a 10-seed sweep found real average improvement in rotation-to-rotation stability (roughly 10–18% lower spread) alongside genuine seed-to-seed variation, including one seed no better than today's split.

Lake Powell's case adds a distinct, harder constraint: because 47% of its rows sit in a single HUC8 sub-basin, no partitioning scheme built from whole HUC8 units can spread it much further than that without splitting a sub-basin itself (which would reintroduce the near-site leakage the whole HUC-grouped design exists to prevent). Some concentration of a single large, well-sampled waterbody is close to unavoidable at this spatial resolution - a further argument for exposing models to more of Lake Powell's range through repeated splits and ensembling, rather than expecting any one split design to distribute it evenly.

The upstream-decision spot check above adds a third piece: the split doesn't just affect final-evaluation performance, it reaches back into the decisions that produced today's feature set and hyperparameters in the first place. Two features (swir1_corr7, tmax_degC_prev30) show a consistent, repeated case for reconsideration that production's single HUC4 split never gave them, and xgboost's hyperparameters move by a real amount once the CV pool is exposed to more of Lake Powell and HUC4 1701. That's a reason to sequence the next step carefully rather than skip straight to implementation.

What this confirms for the next step

These results sharpen, rather than change, the outlier-HUC investigation's recommendation: build a larger ensemble across multiple partition assignments - different seeds, and optionally finer HUC8-level grouping - instead of treating the current single HUC4 split (or any single replacement for it) as ground truth. The 10-seed sweep here demonstrates concretely that different reasonable assignments produce a real distribution of outcomes, not a single better answer, so the value is in pooling across several rather than picking one. A larger ensemble also gives every model more cumulative exposure to hard-but-real regimes like HUC4 1701's clear forested lakes and Lake Powell's dynamic range, since a regime excluded from training in one split's draw is likely included in another's. But the upstream spot check means this shouldn't be implemented directly on top of today's fixed intersection-16 feature set and hyperparameters - both were chosen under exactly the single-split conditions this report just showed are unrepresentative, and at least a lightweight, multi-split re-selection of both should come first.
